Offline Living Dex Tracker & Pokédex (Gens 1–7)

1. Project Overview
A standalone offline web/mobile app built with Expo (React Native), TypeScript, and Tailwind CSS (via NativeWind). Designed for tracking living dex progress across multiple games/generations (Gens 1 through 7 / 3DS era) using pre-bundled local data and assets.

2. Architecture & Data Strategy
Data Origin: Offline static JSON databases (assets/data/) and PNG sprites (assets/sprites/) generated by scripts/build_dex_db.py.

Zero Network Requests: The mobile app makes 0 runtime network calls.

State Management: React Context (AppContext.tsx) persisted locally via @react-native-async-storage/async-storage.

3. Local Data Schemas
Pokémon Record (assets/data/pokemon.json)
id: number (1–807)

name: string

nationalNo: number
catchRate: number (base catch rate out of 255)

localDexNumbers: Record (e.g. { "kanto": 25, "original-johto": 22, "kalos-central": 104 })

types: string[]

baseStats: { hp, atk, def, spa, spdef, spe }

abilities: Array of { name: string, isHidden: boolean, description: string }

megaForms: Array of { id: number, name: string, statOverrides: Record }

evolutionDetails: Array of exact triggers:

trigger, min_level, item, held_item, time_of_day, known_move, location, gender, min_happiness, min_beauty, relative_physical_stats, needs_overworld_rain, turn_upside_down

evolvesFrom: { id: number, name: string } | null

evolutions: Array of { id: number, name: string, details: EvolutionDetail[] }

locations: Array of { locationAreaId: number, locationArea: string, versionGroups: string[] }
locations: Array of { locationAreaId: number, locationArea: string, versions: string[] }
Caught status is stored per game; Living Dex status is global per species.

Move Record (assets/data/moves.json)
id: number

name: string

type: string

category: "physical" | "special" | "status"

power: number | null

accuracy: number | null

pp: number

description: string

learnedBy: Array of { pokemonId: number, versionGroupDetails: Array<{ version_group: string, level_learned_at: number, learn_method: string }> }

4. Game & Generation Mapping Rules
Remake Mapping
Remakes belong to their original generation roster, but use their remake engine mechanics/stats/moves.

SoulSilver / HeartGold: Regional roster = Gen 2 Johto (#1–256). Engine mechanics = Gen 4 (HGSS).

FireRed / LeafGreen: Regional roster = Gen 1 Kanto (#1–151). Engine mechanics = Gen 3 (FRLG).

Omega Ruby / Alpha Sapphire: Regional roster = Gen 3 Hoenn (#1–211). Engine mechanics = Gen 6 (ORAS).

5. App Interface & Feature Requirements
A. Active Game & Context Selection
User selects current game (e.g., SoulSilver, Platinum, White).

App filters views to show the local dex for that game, displaying:

Local Dex Number.

Version Exclusive indicator badges (e.g., "Exclusive to SoulSilver").

Caught status & Living Dex status flags.

B. List Views & Bulk Edit Mode
Toggleable Bulk Edit Mode rendering checkboxes next to all items in active view.

Batch operations: "Set Selected Caught (True/False)" and "Set Selected Living Dex (True/False)".

Master National Dex view showing overall progress across all 807 Pokémon.

C. Pokémon Detail View
Stats: Base stats bar chart.

Forms: Toggle between base form and Mega Evolutions (displaying stat adjustments).

Evolution Tree: Visual flow showing triggers (level, trade items, friendship, time of day).

Locations: Filtered by current game version.

Moveset: Table of learnable moves filtered by current game engine. Each move links to a detail modal displaying type, power, accuracy, PP, category, and effect description.

D. Tools
Type Matchup Tool: Standalone calculator and on-card component taking 1 or 2 types and outputting weaknesses, resistances, and immunities.
